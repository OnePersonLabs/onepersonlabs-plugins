# OPL Borg grilling restart handoff

## Protected preliminary README copy

The preliminary philosophy copy lives in `plugins/opl-borg/README.md`. Everything from `## Why Borg?` through the final `*Resistance is futile.*` is protected: do not alter any of it unless the user explicitly approves the change through the native structured-question tool.

Carry this invariant into any future plan, issue, spec, handoff, or implementation artifact that could lead to README edits.

## Settled assimilation intent

- Extract a donor's technological distinctiveness; do not copy the donor's implementation or product form.
- Treat donor architecture as evidence about the capability, not as the presumptive shape of the destination.
- Ruthlessly refract the recovered value through the receiving collective's goals, constraints, architecture, standards, and existing powers.
- Verify that the distinctiveness survived and improved; structural similarity to the donor is neither a goal nor proof.
- Produce plural collectives with natural, coherent boundaries rather than an unnecessarily accumulated mass.
- Collaborate with the user wherever a boundary or tradeoff is genuinely ambiguous.

## Unresolved design frontier

- Whether an assimilation should be self-erasing after integration or leave a persistent operational surface.
- The practical test for deciding and revising collective boundaries.
- Whether v1 is fully type-agnostic or deliberately starts with a narrower donor/destination class.
- The intended initial audience and the knowledge the workflow may assume.
- The relationship between Borg assimilation and the Sporkflow plugin.
- Donor disposition after assimilation, including migration, replacement, and retirement behavior.
- The `opl-borg` / `$assimilate` naming-collision policy across installed plugins and other Borg collective repositories.

These are frontier questions, not settled requirements. Recommendations remain recommendations unless the user explicitly accepted them.

## Restart procedure

Resume by invoking `$opl-matt-pocock-skills-productivity:grill-me` in a fresh Codex thread. The grilling flow must use Codex's native structured-question tool, not a numbered prose questionnaire.

If the question tool fails, the repaired skill checks `codex features list`. When the feature is disabled, the user can reply `add it for me` to authorize `codex features enable default_mode_request_user_input`; after it is enabled, restart Codex and say `retry`. If the feature is already enabled but the tool still fails, the skill aborts instead of falling back to chat questions.
